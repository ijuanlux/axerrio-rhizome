why the name

One living network,
underground.

A rhizome is how ginger and bamboo grow. Above ground you see separate plants; underground there is one organism feeding all of them. It sprouts wherever it is needed, and if you rip one plant out, the network survives and regrows.

That is the design. One brain (Claude), one root network (the MCP), shoots on every box (agents), shared DNA (the skills). Rip out any single person and nothing dies.

the prize · abs modernization

The modernization
does not ship without this.

The rewrite already exists: the VB6 ERP was ported to .NET 8 and a Svelte client, form by form. The target platform already exists: Kubernetes through Groot, static delivery on CloudFront, databases on RDS. What sits between them is not code and not infrastructure. It is the estate itself: dozens of environments assembled by hand over 25 years, no two alike. Closing that gap is exactly what Rhizome does.

Kill Crystal→ 64-bit→ Linux→ Containers

One chain, not four projects. They unlock together, and everything after them is an estate operation, tenant by tenant.

Ground truth

No migration wave can be planned without knowing, per tenant, the schema version, where every binary lives and what state each box is in. That dataset existed nowhere.

  • Produced live across the whole estate in minutes
  • Refreshed on demand, never stale
  • Turns wave planning from guesswork into a list

The prerequisite, at scale

No tenant moves to the new platform below a minimum database version. A few are ready. Most are not, and every one of them is a bespoke, hand-assembled install.

  • The update runbook makes them repeatable
  • From artisanry to a pipeline
  • The difference between a wave a quarter and a wave a week

Verified landings

Every migrated tenant needs proof it actually works: app launch, schema version, print queues, certificates, reachability. Today that is manual sign-off.

  • Scripted checks instead of consultant hours
  • Evidence attached to every cutover
  • Rollback decisions made on facts

Dev builds the destination. Platform lays the runway.
Rhizome knows every origin box, brings it to the prerequisite, and verifies every landing.

And the window is open right now: the first customer has not gone live on the new platform yet. The runtime chosen for that first go-live sets the pattern for every tenant after it.
